### Config

Loaded from env vars + `/config/config.json`. File config overrides env vars, except `lidarr_url`, `lidarr_api_key` and `download_path` (`ENV_PREFERRED_KEYS`), where a non-empty env var wins. Saved via `save_config()`, which writes atomically (temp file + `os.replace`) and persists only `ALLOWED_CONFIG_KEYS` plus values that differ from the env; handlers that read-modify-write use `update_config(mutator)` so concurrent toggles don't lose updates. API input goes through `coerce_config_value()` (typed int/float/bool/list keys; invalid → HTTP 400). `GET /api/config` and the export never include `lidarr_api_key`; the `SECRET_CONFIG_KEYS` (notification tokens/webhook, AcoustID key, PO token, Apprise URLs, Spotify secret, VPN proxy URL and gluetun API key — not `download_client_api_key`) are shown as `SECRET_MASK` by `GET /api/config`, dropped from the export, and a POSTed or test-route value equal to the mask keeps/uses the saved one (`""` still clears it) — except that the Ntfy test sends the saved `ntfy_token` only when the target is the saved `ntfy_url`, so a masked token can't carry it to a caller-chosen server. `ALLOWED_CONFIG_KEYS` whitelist controls what can be set via the API. Notable config keys beyond the basics: `concurrent_tracks`, `yt_cookies_file`, `yt_force_ipv4`, `yt_player_client`, `yt_retries`, `yt_fragment_retries`, `yt_sleep_requests`, `yt_sleep_interval`, `yt_max_sleep_interval` (Settings › YouTube access › Request pacing; yt-dlp sleeps a random min–max before each download; `_build_common_opts` clamps them to ≥ 0 and max ≥ min), `discord_enabled`, `discord_webhook_url`, `discord_log_types`, `acoustid_enabled`, `acoustid_api_key`, `download_client_enabled`, `download_client_api_key`, `download_client_category`, `yt_po_token` (manual yt-dlp PO token(s), comma-separated), `audio_normalize` (EBU R128 loudnorm, forces re-encode), `yt_pot_provider_url` (URL of a bgutil PO-token provider sidecar for automatic PO tokens; `bgutil-ytdlp-pot-provider` plugin is in requirements and a sidecar is wired in docker-compose), `search_artist_source` (per-track YouTube search artist: `album` default, or `mb_itunes`/`itunes_mb`/`mb`/`itunes` to resolve the real artist for compilations), `save_lyrics` (write a `.lrc` synced-lyrics sidecar per track, fetched from LRCLIB), `apply_replaygain` (measure loudness with ffmpeg and write ReplayGain track tags — non-destructive volume normalization; both run through `metadata.apply_file_extras()` on the final file, which every download path — Lidarr album, manual / retry, YouTube import — must call, and each path records `dl_result["source_format"]`), `track_retry_backoff` (default on; a track that keeps failing waits `scheduler_retry_after_hours * 2^(failures-1)`, capped at 30 days, instead of being retried every cycle forever — issue #90), `max_track_retries` (0 = never give up; otherwise drop a track after this many consecutive failures), `sync_partial_albums` (default off; `lidarr_sync` also caches partially owned monitored albums, see `architecture.md`; `POST /api/config` starts a sync when the value changes), `queue_paused` (default off; while on, `processing._dispatch_next_from_queue()` starts nothing — manual, scheduler and download-client entries all wait, as does the playlist watch (`processing.automatic_downloads_held()`, also true while a restart is pending) — and an album already downloading finishes; toggled by `POST /api/download/queue/pause`, exposed in `/api/stats`; also set automatically by `processing._pause_queue_for_full_disk()` when a track fails with "no space left on device", with one `album_error` notification, so the next albums don't each fail the same way — the user resumes it after freeing space), `ui_accent` (`#rrggbb`, default `#7c5cff`) and `ui_aura_mode` (`cover` | `accent` | `off`) — Settings › Appearance, saved instantly; validated in `coerce_config_value()` (anything but a plain hex is rejected, because `inject_version()` writes the accent into every page's `<head>` as `--accent-base` and the mode as `data-aura`) and normalised in `load_config()`, `explore_country` (two-letter code, default `IT`; charts and YT Music `location`) and `explore_language` (one of ytmusicapi's languages, default `en`); both are validated in `coerce_config_value()` and normalised in `load_config()`. `yt_watch_playlists` (list of YouTube playlist URLs, validated in `coerce_config_value()`; issue #96): `youtube_import._playlist_watch_loop` checks them hourly (and right after a save) and imports every video without a `track_downloads` row as one album via `_execute_playlist_download`, artist/album/year parsed by `explore.album_from_video_title()`, into `<playlist write base>/<Artist>/<Album (Year)>/`. Before each import it waits (quietly, 10 s steps) for the download slot and while the queue is paused or a restart is pending; the Explore artist import likewise starts no release while a restart is pending. A failed video is not retried automatically — the failed-tracks view retries it.

### Optional login (`auth.py`)

Off by default. Turned on from Settings › Security (`POST /api/auth/setup`, which stores `auth_username`, a werkzeug `auth_password_hash` and a generated `auth_api_key` in config.json) or forced by `AUTH_USERNAME` + `AUTH_PASSWORD` env vars. The `AUTH_CONFIG_KEYS` are **not** in `ALLOWED_CONFIG_KEYS` (so `/api/config` and config import can never set them) and `_public_config()` drops them. `require_login()` lets through `PUBLIC_PATHS` / `PUBLIC_PREFIXES` (login, static, manifest, sw, health, Newznab and SABnzbd, which have their own API key), a session cookie, or the `X-Api-Key` header / `?apikey=`; otherwise pages redirect to `/login?next=` and APIs answer 401 with `X-Login-Required: 1`, which `app.js` turns into a redirect. The session key is created lazily (`_LazyKeySessionInterface`) in `/config/secret_key`.

### Notifications

Telegram, Discord webhooks, Ntfy push and Apprise (`apprise_urls`, one URL per line, `apprise_log_types`) notifications, filtered by `log_type` (e.g., `partial_success`, `album_error`). Ntfy is called with a JSON body on the **server root** (`POST {ntfy_url}/`, topic inside the JSON — ntfy ignores JSON posted to `/<topic>`) and an integer priority (1–5). Exception messages are logged through `_redact()` so bot tokens / webhook tokens never reach the logs.
